# `hard_examples.tsv` 작성 가이드

이 파일은 기존 학습 모델이 자주 틀리는 문장 유형을 추가로 학습시키는 예시 모음입니다. 학습 코드는 [medium_train_v2.py](medium_train_v2.py)의 `load_hard_examples()`에서 읽습니다. 이 TSV를 수정한 뒤 `train_cycle.sh`를 실행하면 Windows 파일이 WSL로 동기화되고 보강 학습을 시작합니다.

## 편집할 파일

Windows 프로젝트의 다음 파일을 편집합니다.

```text
C:\Users\sierra\Documents\ESP32-S3-Bert-Kluster\Bert\hard_examples.tsv
```

VS Code나 메모장으로 열고 UTF-8 텍스트로 저장합니다. WSL의 복사본을 직접 수정하지 않습니다. 쉼표로 구분하는 CSV로 바꾸지 말고, 확장자도 `.tsv`로 유지합니다.

## 한 줄의 형식

데이터 한 행마다 아래 네 열을 순서대로 씁니다.

```text
영어 문장<TAB>장치<TAB>동작<TAB>목표 세기

예:
please do not stop the fan<TAB>-<TAB>none<TAB>-
```

`<TAB>`은 탭 키로 입력하는 구분자라는 뜻입니다. 글자 그대로 `<TAB>`이라고 쓰지 않습니다. 각 행에는 탭 구분자가 정확히 3개 있어야 하고, 문장 안에는 탭을 넣지 않습니다. 첫 행을 헤더로 바꾸거나 열 이름 행을 추가하지 않습니다. 주석을 쓰려면 행 맨 앞에 `#`을 둡니다. 빈 줄과 주석 행은 무시됩니다.

| 열 | 허용 값 | 작성 기준 |
| --- | --- | --- |
| 문장 | ASCII 영어 문장 | 모델이 실제로 받을 표현을 씁니다. 한 줄에 문장 하나만 씁니다. |
| 장치 | `led`, `motor`, `fan`, `-` | 제어 대상 장치. 명령이 아닌 문장은 `-`로 씁니다. |
| 동작 | `on`, `off`, `change`, `none` | 의도한 동작. `none`은 제어 명령이 아닌 문장입니다. |
| 목표 세기 | `0`~`7`, `-` | 명령의 최종 세기. `none` 문장은 `-`로 씁니다. |

장치와 동작은 소문자 그대로 써야 합니다. `none` 행은 장치 `-`, 동작 `none`, 세기 `-`를 써야 합니다. `none`이 아닌 행은 장치 중 하나와 숫자 세기를 지정합니다.

# (중요!) 라벨을 정하는 법

라벨은 모델이 예측한 값을 복사하는 게 아니라, 문장을 올바르게 이해했을 때 의도한 정답으로 작성합니다. 출력의 `OK`, `HOLD`, confidence는 학습 라벨이 아닙니다.

- `on`: 장치를 켜고 목표 세기로 설정합니다. 일반적으로 최대 세기라면 `7`을 씁니다.
- `off`: 장치를 끕니다. 보통 세기는 `0`으로 기록합니다.
- `change`: 켜기나 끄기가 아니라 세기를 조정합니다. `amount`에는 **변경 후 목표 세기**를 씁니다. `2`는 두 단계 내리라는 뜻이 아니라 최종 세기를 2로 설정하라는 뜻입니다.
- `none`: 질문, 상태 설명, 금지·부정 문장, 잡담처럼 장치를 조작하면 안 되는 문장입니다. 장치와 세기는 모두 `-`로 씁니다.

예시:

```text
make the desk lamp a little dimmer<TAB>led<TAB>change<TAB>2
switch the motor off<TAB>motor<TAB>off<TAB>0
should we start the desk fan<TAB>-<TAB>none<TAB>-
the fan was noisy this morning<TAB>-<TAB>none<TAB>-
```

각 `<TAB>` 표기를 실제 탭 하나로 바꿉니다. 마지막 두 문장은 팬을 조작하라는 요청이 아니라 질문과 과거 상태 설명이므로 `none`입니다.

아래 블록은 필드 사이에 실제 탭 문자가 들어 있어 파일에 붙여넣을 수 있습니다.

```text
make the desk lamp a little dimmer led change 2
switch the motor off motor off 0
should we start the desk fan - none -
the fan was noisy this morning - none -
```

## 어떤 오답을 추가할까

1. `last_unseen_errors.tsv`나 실제 입력에서 잘못 이해한 문장을 찾습니다. 예측 결과와 confidence는 참고만 하고, 정답 라벨을 먼저 사람이 결정합니다.
2. 모델이 배워야 할 의도와 헷갈리는 표현을 만듭니다. 고정 평가셋 문장을 그대로 복사하지 말고 비슷한 뜻의 새로운 표현으로 바꿉니다. 평가 문장을 그대로 넣으면 누수 검사에서 학습이 중단될 수 있습니다.
3. 혼동을 일으킨 장치·동작 예시를 넣을 때는 관련된 `none` 예시도 생각합니다. 예를 들어 상태 질문을 명령으로 오해했다면 명령 예시만 추가하지 말고, 질문이나 상태 문장에 올바른 `none` 라벨도 추가해 오작동을 막습니다.
4. 저장하고 보강 회차를 한 번 실행한 뒤 점수를 확인합니다. 같은 문장을 여러 줄로 중복하지 않습니다. 현재 코드는 TSV의 각 행을 **5회 반복**해 보강 학습 데이터에 넣으므로, 행을 중복하면 해당 문장의 영향력이 더 커집니다.

고정 평가셋의 `UNSEEN` 문장을 그대로 학습 예시에 복사하지 않습니다. 이 평가셋은 튜닝 중 성능 변화를 확인하기 위해 따로 둡니다. 학습 완료 뒤 모델이 채택되었는지 보류되었는지는 자동 회차 로그에서 확인합니다.

## 자주 나는 형식 오류

- 열을 탭이 아니라 공백이나 쉼표로 나눔
- 행의 열이 4개가 아님
- `none` 행에 장치나 숫자 세기를 씀
- `none`이 아닌 행에서 장치나 세기를 `-`로 씀
- 동작을 `turn on`, `stop` 같은 자유 문장으로 씀 (`on`, `off`, `change`, `none` 중 하나여야 함)
- 새 표현을 테스트하려고 TSV에 넣고, 그 문장을 고정 평가 문장과 정확히 똑같이 작성함

형식 검사 오류가 뜨면 표시된 파일 줄 번호에서 탭 개수와 라벨을 고친 뒤 다시 저장합니다.
